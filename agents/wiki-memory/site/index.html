Wiki memory

An agent that keeps a wiki instead of re-reading its sources
About Code

    About this demo

    What wiki memory is

    Plain retrieval (RAG) re-reads raw chunks of your documents for every question. With wiki memory, an agent instead maintains a set of markdown pages: when a source arrives it updates the pages about each person, system and policy the source mentions, links them, and records what changed. Questions are answered from those pages, which already reflect every source read so far.

    The pattern was written up by Andrej Karpathy as “LLM Wiki” (April 2026): raw sources that are never edited, a wiki the model owns, and a schema file that tells it how to keep the wiki. Three operations keep it going: ingest, query and lint.

    What is scripted and what is computed

    • Scripted The five sources, the pages the agent writes at each step, the step notes and the example answers were written by hand to show what a careful LLM maintainer would produce. No model was called.
    • Computed Everything derived from those pages is computed by code and covered by tests: the diffs, the link graph, index.md, log.md, the lint findings, the BM25 rankings and the fact checks.

    How step 3 compares the two

    Both sides use the same BM25 ranker. Chunk RAG ranks paragraph chunks of the raw sources and keeps the top . The wiki side ranks the wiki's topic pages (entities, concepts and the overview) and keeps the top , standing in for an agent that reads index.md and opens the most relevant pages. Struck-through claims are shown but don't count as current.

    The fact checks look for whole statements, so “lowered from 100 to 50” isn't counted as stating 100. With an embedding retriever, or a larger corpus, the rankings would differ; this is one small example, not a benchmark.
