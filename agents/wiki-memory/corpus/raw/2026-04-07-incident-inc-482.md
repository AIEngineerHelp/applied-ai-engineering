# Incident INC-482: nightly exports failed

Severity 2. 4 to 6 April 2026. Incident lead: Amara Osei.

## Summary

The nightly export job failed three nights in a row. About 210 export requests were delayed by up to three days.

## Cause

On 3 April the Payments team lowered the Billing API limit from 100 to 50 requests per second per client, to protect the API during a database migration. The export job still called it at 80 requests per second, received HTTP 429 responses, and gave up when its retries ran out.

## Fix

- The export job now calls the Billing API at 40 requests per second and backs off when it receives HTTP 429.
- Payments will keep the 50 requests per second limit permanently.

## Follow-ups

- Payments will announce limit changes in the #payments-changes channel at least a week in advance. Jun Park owns this.
- Ledger Export now alerts if the nightly run has not finished by 06:00 UTC.
