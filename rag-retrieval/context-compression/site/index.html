03 / THE MECHANISM

A filter between reading and reasoning.

Compression selects source text.
Summarization writes new text.

01

Split without rewriting

Turn the input into paragraphs or sentences. Record original offsets. Keep code fences whole and attach the headings that give a unit its meaning.

source → units + offsets
02

Score for this question

Lexical ranking matches terms. MMR penalizes repetition. BGE uses embedding similarity; remote Laya judges unit relevance. LLMLingua-2 classifies which tokens to preserve. LLMLingua prunes with causal-model perplexity; LongLLMLingua adds question-conditioned ranking and pruning. None guarantees that every necessary fact survives.

question + focus → ranking
03

Pack the budget

Try units from highest score to lowest. A unit fits only if its headings and separators fit too. Then restore source order. Word deletion keeps exact word spans; hosted output has no source offsets, so we do not invent its dropped view.

ranking + budget → context

04 / THE TRADE-OFF

Fewer tokens is a metric.
Enough evidence is the goal.

Try a smaller budget. Turn off the read’s focus. Switch to truncation. A compressor can produce a very small context while losing exactly the sentence that matters.

Retrieval can fail first

A compressor cannot recover a fact your retriever never returned. The RAG example reports those misses separately.

Context has dependencies

A correction, a negation or a table heading may change another sentence’s meaning. Selection by relevance alone cannot guarantee safety.

Savings have overhead

A live compressor adds inference and network time. Measure total latency, output quality and cost—including prompt caching—before claiming a win.

Budget sweep
