02 / BEYOND LEXICAL

What models change.

The same split → score → pack idea,
with a model doing the scoring.

The four techniques above score text with word counts you can check by hand. These methods replace that scoring with a model. They fix some of the failures you just saw and bring new ones. Adapters for each are included in the code, but none run on this page: local models are disabled, and remote ones need keys and your consent. Nothing below is a measured result.

Semantic ranking

BGE embeddings

Scores each sentence by how close its meaning is to the question, not its exact words.

question + each sentencebge-small-en-v1.5 embeds bothcosine similaritysame budget packer
Would help here
The synonym miss. “Money back on a yearly plan” and “full refund for annual subscriptions” share no words but are close in meaning.
Watch out
Close in meaning isn’t the same as needed. An exception that contradicts the question can score lower than a sentence that restates it.

Learned word deletion

LLMLingua-2

A small classifier predicts, for every token, the probability that it should be kept. It was trained on compressions written by a large model.

textBERT-size token classifierkeep probability per wordkeep the most likely words
Would help here
Word deletion’s broken grammar: a trained model learns that “not” and “except” carry meaning.
Watch out
It never sees the question. At tight budgets it keeps what’s generally informative, which may be the wrong section.

Adapter included. Not run on this page: local models are off.

Perplexity pruning

LLMLingua

A small language model reads the text and drops the tokens it finds most predictable. Predictable tokens add little information.

textsmall causal LM (Phi-2 here)surprise per tokendrop the least surprising
Would help here
Trimming filler and boilerplate inside long passages, not just whole sentences.
Watch out
Question-blind. A rare-but-irrelevant detail looks surprising, so it may survive while the answer is pruned.

Adapter included. Not run on this page: local models are off.

Paper ↗

Question-aware perplexity

LongLLMLingua

Asks how much each document makes the question more likely, ranks and reorders documents, then prunes tokens inside them.

question + documentssmall causal LMrank and reorder documentsprune tokens
Would help here
Many retrieved passages where the answer is buried in the middle, the case it was designed for.
Watch out
Several model passes per request add latency. Reordering changes what the answerer reads first.

Adapter included. Not run on this page: local models are off.

Model as relevance judge

Laya remote

Asks a remote model a typed yes/no question for each sentence (“is this relevant?”) and uses the probability as the score.

question + each sentenceremote model judgementprobability of “relevant”same budget packer
Would help here
Questions that need understanding rather than matching: “does this sentence change the answer?”
Watch out
One judgement per sentence costs time and money, and the probabilities need checking on real data.

Adapter included. Needs a configured remote server and your consent per call.

04 / THE TRADE-OFF

Fewer tokens is a metric.
Enough evidence is the goal.

Try a smaller budget. Turn off the read’s focus. Switch to truncation. A compressor can produce a very small context while losing exactly the sentence that matters.

Retrieval can fail first

A compressor cannot recover a fact your retriever never returned. The RAG example reports those misses separately.

Context has dependencies

A correction, a negation or a table heading may change another sentence’s meaning. Selection by relevance alone cannot guarantee safety.

Savings have overhead

A live compressor adds inference and network time. Measure total latency, output quality and cost—including prompt caching—before claiming a win.
