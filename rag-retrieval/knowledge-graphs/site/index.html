2 · The idea

What is a knowledge graph?

Instead of searching for passages, store the facts themselves, and follow them.

A knowledge graph stores facts as entity → relation → entity: QX-7 radio chip → part of → Atlas-3; Osterby Water Utility → uses → Atlas-3. An LLM reads each document once and extracts facts like these, each with the sentence it came from, and names that mean the same thing are merged into one entity.

To answer a question, code starts at the entity the question names and follows the relations, one hop at a time. Each hop can come from a different document, so the graph joins facts that no single passage holds.

Six words used below

Entity
A thing the documents talk about: a person, team, product, part, supplier or customer. In the drawings, its shape shows its type.
Relation
A typed link between two entities, such as SUPPLIES, PART_OF or USES.
Triple
One fact, written entity → relation → entity, kept with the exact sentence it came from.
Entity resolution
Deciding that two names, such as “Varnell Semi” and “Varnell Semiconductor”, are the same entity, and merging them.
Traversal
Answering by following relations from one entity to the next, one hop at a time. Here, a Cypher query run on Neo4j.
Schema
The allowed entity types and relations, and which types each relation may connect. The extractor must follow it; code rejects anything outside it.

    5 · When the graph loses

    The graph only knows what extraction captured

    Ask what the QX-7 incident review recommended. The answer is a sentence of prose, not a relation between two entities, so it never became an edge.

    Use the graph when

    The answer is a chain of facts across documents: impact (“who is affected if…”), ownership, dependencies, “how is X connected to Y”, or a count over many entities. And when you can say in advance which relations matter, so a schema can capture them.

    Chunk search is enough when

    The answer sits in one passage: a recommendation, a reason, a definition, a number in prose. Or when questions are open-ended and no schema could anticipate them.

    Where the model went wrong

    Real mistakes from the recorded runs, found by the author's review and by the tests. None of them is staged.

    6 · Who does what

    The LLM, the code and a person

    A knowledge graph is not just a prompt. The LLM turns text into facts and questions into queries; code checks the facts and runs the queries; a person decides what the graph may hold and settles what neither can.

    The LLM

    • Extracts entities and relations from each document, against the schema, as structured output.
    • Quotes the sentence each relation came from.
    • Checks merges the rules can't decide, with the sentences for context.
    • Translates questions into Cypher (text-to-Cypher), and repairs a query that returns nothing.
    • Writes the answer from the query and its rows.

    Code

    • Validates every triple against the schema.
    • Checks that every quote exists verbatim in its source.
    • Merges names by deterministic rules, within a type, and refuses ambiguous ones.
    • Loads the graph with provenance on every edge: document, date, quote, run.
    • Blocks any query that could write or run unbounded, then runs it read-only with a timeout.
    • Scores every answer against the facts it needs.

    A person

    • Designs the schema and changes it as needs change.
    • Decides the merges the LLM was unsure about.
    • Reviews extraction mistakes and which queries may run, with which permissions.

    From 25 documents to millions of facts

    8 · Recap

    So what is a knowledge graph?

    • It stores facts as entity → relation → entity, each with the sentence it came from, instead of storing passages.
    • An LLM extracts the facts once; code follows them. A traversal joins facts from documents that never mention each other, which chunk search can't do.
    • It only knows what extraction captured, and extraction makes mistakes. Reasons and recommendations stay in the text, so most systems combine the graph with chunk search, and a person reviews what the model is unsure about.

    Not wiki memory. A knowledge graph stores typed facts that code traverses. Wiki memory stores pages of prose that an agent reads and rewrites.

    This is a teaching demo, not a production system. Twenty-five short synthetic documents, one recorded extraction, and a person's review written by the author. See Taking it to production.
